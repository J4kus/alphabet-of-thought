# Change Log

All notable changes to the "aot" extension will be documented in this file.

Check [Keep a Changelog](http://keepachangelog.com/) for recommendations on how to structure this file.

## [1.13.0] - 2026-11-01

- **A table never nests by indentation.** A sub-Example names the row it sits under in a `parent (thing)` column — named `parent`, its `(alias)` the table's own Concept, lowercased. It is the column the CSV mirror has always carried the tree in. A parent cell names the nearest row above of that name, else the first below, so a sort can leave a parent below its child. A name no row carries, a row naming itself and a circle of parents are errors.
  - *Breaking:* a row's indent means nothing now. A table nested by indent reads as flat rows, with no warning, and Format Document draws them flush. Pre-1.12 bordered tables read as rows with an empty name cell, which is an error.
  - `Tab` and `Shift+Tab` in a table never indent, with lines selected or not: they move between cells. A whole table is re-filed with VS Code's own `Ctrl+]` / `Ctrl+[`.
  - **Nest Row Under the Row Above** and **Lift Row Out of Its Parent Row** write the parent cell, adding the column when the table has none. Deleting a row takes the rows under it, wherever they stand.
  - Parent cells link to the row they name (Ctrl+click, hover, rename), and the Outline lists a table's rows flat under its header.
- **Dividers.** `-----|---` between rows groups them, as a blank line groups an outline. Dividers are kept and redrawn to the columns' widths; every key steps over them, and a sort stays within its group. A `---+---` rule is no divider now.
- **The flip keeps your place.** `Ctrl+Alt+T` lands the cursor on the same idea in the other form: the same value, cell, Example or column, as far into it as it was. An empty cell lands on its Example's name in line form, and comes back as that cell.
  - A Concept with no Examples flips to its header alone (`Person|age|city`).
  - Blank lines above Examples become dividers, and back.
  - A row with an empty name keeps its values on the way out.
  - The grid no longer swallows a table written straight after the Concept: a blank line keeps them apart.
  - A maintained `... N more in a.aot:3` note stays under the table's last row and no longer forces the merge form, so a table carrying one flips and flips back unchanged.
- **The file saved last overrides the other.** Between a `.aot` and its CSV, the two files' save times decide, even where the other file was edited too. Nothing is merged and nothing is remembered, so a fresh clone, a moved folder and a new profile behave like anywhere else.
  - Saved last, the `.aot` rewrites the CSV. Saved last, the CSV gives the `.aot` every cell where the two differ: an emptied cell empties, a new row arrives, and a row it no longer lists is deleted with nothing asked (a row whose sub-row it still lists stays, and a notice says so).
  - No notice says what was overwritten. In a `.aot` open in the editor, `Ctrl+Z` brings it back.
  - A column comes from the `.aot` alone.

  This fixes three ways edits were lost:
  - a `.aot` changed while the editor was closed being reverted;
  - a CSV older than the `.aot` overwriting it;
  - a fold saving your unsaved work. A CSV saved last now overrides the table in an open `.aot`, unsaved edits to it included, and leaves the file for you to save. Anything else unsaved in that file stays. A CSV saying what the saved `.aot` says overrides nothing.

  Also:
  - A `.aot` saved by another program, or a pull, rewrites the CSV as soon as the file watcher hears it.
  - A Concept written in several files mirrors their union, and each row's edit goes to the file that lists it.
  - `aot.tableCsvSyncMode: manual` syncs only on **AOT: Sync CSVs Now** (`Ctrl+K Y`; it was *Import Edited CSVs*), where the same rule decides.
  - A fold no longer writes an inherited value down as an Example's own, and no longer repeats a nested `- ` Example at the top with a literal `parent:` line.
- **Rename by typing.** Type over a used name, and once the cursor leaves it the extension counts the uses still saying the old name, across the workspace (`3 uses — 2 here, 1 in bank.aot`), and offers to update them all in one edit. Other files are left unsaved for review. The offer stays on the declaration's lightbulb until it is taken, dismissed or moot, and says so when the new name already names another of its kind. Undo and redo never start one.
  - **F2 reaches the whole workspace too**: a Concept's spelling in other files, and every crosslink and `@` reference to it there.
  - The ghost text drops "F2 renames them all".
- **Findings elsewhere wait while you write.** Typing a first child no longer flashes "'Parent' has 1 sub-Concept" at the parent mid-thought. From the first edit, a finding that is new, and not on a line you edited, waits until the cursor leaves what you are editing (the edited node's parent and everything under it), you save, or you switch editors. A finding already on screen stays, a fix shows at once, and your own lines speak. A status item counts what waits, and a click shows it. This replaces the 600 ms grace on the two lone-child warnings.
- **`Concept: value` is the Concept's default.** `Currency: EUR` says what any attribute typed by `Currency` reads where nothing values it. It is no longer an Example, so it is no CSV row, no `@Currency` row and no FCA object.
  - A value equal to the default links, dotted, to the Concept's line, and is offered first in completion.
  - A table states defaults in its header: `Currency: EUR|symbol`, and `Order|tax rate: 0.2|price`, whose empty cells read `0.2`.
  - A derived default (`Currency: EUR =pick()`) is an error, for now.
  - *Consequences:* a CSV that held only such an inline Example (`Run Command.csv`, `Click DropDown.csv`) is archived as `_X.csv` on the next save. A capitalised `Name: value|…` line is now a table's header, where 1.12 read it as a value holding a pipe. `alphabet of thought.aot` loses seven dependency warnings that only the inline Examples produced.
- **`=` defines, and `==` escapes.**
  - On an attribute declaration `=` is the definition 1.12 spelled `==`: `vat =@price*0.2` on a header cell is a column calculation, and `status =("draft", "sent")` lists the allowed values.
  - In a value, a doubled `=` after a space is a literal one: `note: a == b` reads `a = b`.
  - *Breaking:* the older spellings no longer read. `\=` is only a backslash and an `=`, and `==` on a declaration is part of its name.
  - The hoist quick fix, the reconcile and the breach checks no longer turn an escaped value into a derivation.
- **Gödel numbers are computed as exponent vectors**, never as the integers they stand for unless one is shown. On a 2,000-row table, a hover went from 6.7 s to 0.6 ms, rules 15–16 from 3.5 s to 7 ms, and a lint from 0.9 s to 0.1 s. Primes come from a cached sieve. A hover shows a large number as `≈ 4.12 × 10^1,234 (1,235 digits)`, a clash shows its factorisation, and `verify.js --godel` adds the digit count. See [docs/godel-numbers.md](docs/godel-numbers.md).
- **The `... N more in …` note:**
  - a file name with spaces links (`bank recon.aot:14` never did);
  - the link lands on the Concept's current line;
  - hovering `N more` lists those Examples where they are written, and hovering a file name lists that file's;
  - an Example two peers list counts once.
- **A Concept's alias links the Concepts its words name**: `Human (Natural Person)` links `Person`.
- **Fixed:**
  - A sub-Example no longer inherits its parent Example's values in its Gödel number, the FCA context, the CSV mirror or Python: a part inherits nothing from its whole. `examples()` in Python now fills in inherited Concept defaults.
  - The Gödel numbers type an attribute by its `(alias)`, as the FCA audit and the crosslinks always did.
  - The table editor and the linter agree where a table ends at a row shallower than its header.
  - "Define … for the whole column" is offered only for a source that reads as Python.
  - The grammar colours a row whose first cell holds `a=b`.
  - git is started only by its absolute path from PATH, never by bare name inside a repository.
  - The CSV mirror's file cache is checked by content, so a file rewritten to the same size within one clock tick is read anew.
- See [docs/features-1.13.md](docs/features-1.13.md).

## [1.12.0] - 2026-09-30

- **Python sees sub-Examples.** `@Thing` holds every Example in the Concept's scope, sub-Examples included. Where they nest, a `parent` column carries the tree, as the CSV mirror writes it. A value on an Example reaches the Examples beneath it (`@Child 1@age`).
- **Several derivations in one table row.**
  - `Ctrl+Enter` runs the one in the cursor's cell, or on the row's name, all of them. Before, it always ran the left-hand one.
  - The row has one inlay naming its cells (`✓ vat, net · 3 ms · 16:04`), and hover answers for the cell it is over.
  - A `|` inside a later cell's Python is the Python's, as it already was in the first cell.
  - **Calculated columns:** when every row derives a column alike, the lightbulb moves the derivation onto the header as `==`, leaving each cell its value.
  - A header's `==` definition no longer writes over a cell that carries a derivation of its own — the nearer word wins, as it always did in line form.
- **A bare `=` line writes Concepts.** `=load_all()` on a line of its own returns tables by name. A new name is written at the line's indent beneath it; a Concept already in the file is filled where it stands; one with a derivation of its own is left to it, with a warning that two places return it (the line itself ran fine); nothing is ever deleted. `@Sales` elsewhere reads the live table. The park key takes the line out and puts it back above the Concept that stood beneath it. Before, the line parsed as a Concept named `=load_all`.
- **No flip lightbulb.** It lit the bulb on every line of every Concept with Examples. The flip stays on `Ctrl+Alt+T`, `Ctrl+K T`, the right-click menu and the Command Palette.
- **The column keys work from a declaration line.** `Alt+Shift+←` on `age` under a Concept written as lines deletes that column (a new `aot.inColumn` context; `Tab` there still indents). In a table, no column key moves, copies or deletes the name column any more — before, `Alt+Shift+←` there wiped the Concept's name and every Example's.
- **A sub-Example may not carry the name of an Example it sits under** (error rule 24).
- **Stale `...` notes are deleted on save.** Once no other file lists a Concept, its `... N more in …` line is removed; with `aot.autoReconcile` off it is a warning.
- **Python in WSL.**
  - `python3` is tried before `python` off Windows.
  - Each operating system has its own uv environment (`.venv`, `.venv-linux`, `.venv-darwin`), so a checkout used from Windows and WSL keeps both.
  - Linux caps memory by data size rather than address space, so numpy and pyarrow import under it on many-core machines.
  - numpy's BLAS is held to four threads unless you set otherwise.
- **Stable Gödel numbers** in `aot.files/godel.tsv` (`aot.godelRegistry`). Adding an attribute renumbers nothing, and one attribute has one prime in every file and branch. `verify.js --workspace --primes` writes it.
- **Hover shows a node's content**: `G` as a factorisation, each attribute with where an inherited one came from, what it overrides, and the nearest sibling with how it differs.
- **Three warnings from the Gödel numbers**, none in `V`:
  - a value every child states belongs on the parent (15), with a "move up" lightbulb that also drops a table column;
  - a default every child overrides is in force for nothing (16);
  - the same content under two names in two files (17), with the synonym lightbulbs.
- **`--diff` recognises renames and moves**, and `--diff-rev REV file` diffs against a git revision.
- **git merges an `.aot` by meaning.** **AOT: Set Up Git Merge for .aot Files** sets `verify.js --merge` as the merge driver ([`src/merge.js`](src/merge.js)):
  - A rename against a value change, neighbouring attributes, two cells of one row and two added siblings all merge cleanly.
  - One attribute changed two ways conflicts on that line alone.
  - A replay guard, a per-prime arithmetic check and a no-new-errors check fall back to git's own merge whenever the result cannot be vouched for — the last catches a rename onto a name the other side gave a new Concept, which each node's number alone does not.
- See [docs/features-1.12.md](docs/features-1.12.md).

- **A repository can carry its own Python environment, set up with uv** ([`src/uvenv.js`](src/uvenv.js)). **AOT: Set Up Python Environment (uv)** runs start to finish:
  - It writes `aot.files/pyproject.toml` with the libraries you pick. A repository that is already a uv project is used as it is.
  - It locks the project with `uv lock --no-build`.
  - It shows what the lock would install, naming any package from outside PyPI, before anything happens.
  - Only then does it run `uv sync --locked --no-build --no-install-project --compile-bytecode`: exactly the lock, from built wheels alone, compiled to bytecode as it installs. Without that, a session compiled pandas from source every time, over 40 s, and a run queued behind the warm-up timed out.
  - A request's timeout now starts when the runtime reaches it, not when it was sent. The runtime answers one request at a time, so a run waiting behind a slow warm-up no longer counts that wait against its own 15 s.
  - A run never installs anything, and says once when the project moved on since the setup.
  - `aot.python.manager` (`auto`, `uv`, `python`) chooses which Python runs. A uv environment starts isolated (`-I`), and only as it was set up here: the setup records its interpreter's hash, so a `.venv` a repository arrived with, or one whose interpreter changed since, is never run.
  - A missing library's message says to add it to `pyproject.toml` and run the setup. **Show Python Environment** says which environment it is.
- **The Python a `.aot` carries is asked about, piece by piece.** A derivation or bound written in this editor runs without a question, saved or not. One that arrived from outside is asked about before anything starts, naming the lines and the code. That covers a pull, a clone, a store coming home, a CSV folded back, and a peer file reconciled. Until now only the Python *files* were asked about, so a pulled change to a derivation ran on the next `Ctrl+Enter`.
- **Data never becomes code.** The value a result writes has any derivation-opening `=` escaped as `\=`, and a column or row name that would read as a bound or a derivation has its operators made full-width. So a downloaded table holding `x =os.system(…)`, or a column named `n >=evil()`, stays text rather than running on the next `Ctrl+Enter`.
- **The CSV mirror no longer turns an escaped `=` into a derivation.** A value exported through `aot.files/<Concept>.csv` lost its `\=` and came back unescaped, and a line-form `|` came back as `¦`. Either difference made the catch-up fold rewrite the value, so `Flags \=a() | b()` returned as a live derivation, `Flags =a() ¦ b()`. The fold now escapes what a CSV brings and reads `|` and `¦` as one value, so the mirror's own CSV folds back as no change.
- **The derivations' Python is held to guards, set before any repository code runs and never lifted.** All user settings:
  - Memory is capped by the operating system (`aot.python.maxMemoryMb`, 4096).
  - No other program may start (`aot.python.allowSubprocess`, off). On Windows a job object refuses the second process outright; elsewhere Python refuses the calls.
  - The network beyond this machine can be refused (`aot.python.allowNetwork`).
  - The places credentials are kept are refused (`aot.python.protectCredentials`, on): `~/.ssh`, `~/.aws`, the browsers' profiles, the Windows credential store and the rest.
  - The process starts without the editor's secrets: `*TOKEN*`, `*SECRET*`, `*PASSWORD*`, the ssh agent's socket, and VS Code's askpass handles are withheld.
  - Python's own refusals are audit hooks, a guard against the ordinary payload rather than a sandbox, and the README says so.
- **A result that looks like a credential is not written into the file.** That covers a private key, or an AWS, GitHub, Slack, Anthropic, OpenAI-style or Google key or token. The file is committed and pushed, so the result is refused with a message saying why.
- **The settings that decide what runs are user settings only.** `aot.python.enabled`, `.manager`, `.path`, `aot.uv.path` and the guards cannot be set by a repository's `.vscode/settings.json`, so no repository can turn Python on, choose the program that runs, or loosen a guard.
- **`python` and `uv` are found on PATH, never beside the run.** On Windows a bare command name is also looked up in the folder the process starts in, and a run starts in `aot.files`, where a repository could plant a `python.exe`. Both are now resolved to absolute paths from PATH's absolute entries before launch.
- **Consent hashes are SHA-256** rather than SHA-1, whose collisions can be chosen. Files allowed before are asked about once more.
- **"Show Changes" when a Python file changed outside the editor.** Each allowed version is kept in the extension's own storage, so the question opens it beside the file as it is now.
- **Every derivation is Python, and the formula language is gone** ([`src/python.js`](src/python.js), [`src/aot_runtime.py`](src/aot_runtime.py), [`src/pyshape.js`](src/pyshape.js)). The spreadsheet language behind `=` — `sum()`, `xlookup()`, backtick text, `or()`, recomputed on every keystroke — is removed, evaluator and all, and Python stands behind the one `=` in its place.
  - **Where a derivation goes.** On a value or a grid cell it computes the value in front of it. On a **Concept line** (`Sales =by_month(@raw)`) it writes the Concept's table, whose rows it owns outright. The line becomes the table's header, with the Concept and its derivation in the first cell, rather than a table beneath it repeating its name. Its rows are numbered `1`, `2`, `3`, and every column of the frame stays a column. **A column named after the Concept** (`quarter` under `Quarter`) names the Examples instead, unless two rows would share a name or one would have none.
  - **What comes back.** `@` arrives typed: a Concept as a DataFrame, a column as a Series, a value strictly (`2026-01` stays text), another derivation as its **live result**. A picture or a long text is written into `aot.files` with its path as the value, and a frame on an attribute is summarised, `<DataFrame 1,204 rows × 4 cols>`.
  - **Where the code lives.** Longer code lives in the file's sidecar, `aot.files/<file>.py`, or in **any Python file of the repository**, named as a module with no import. `=finance.revenue(@Sales)` finds `finance.py` in `aot.files`, at the root or anywhere else in the repository; `=tools.finance.revenue(…)` takes a dotted path; `aot.use("tools/my helpers.py")` takes a path. The standard library and installed packages come first, so nothing in the repository can shadow them.
  - **Constraints are Python too.** A bound (`cap <=@price*1.5`, `status ==("draft", "sent")`) is checked, per value and in one round trip, when Python runs. A breach is a warning on the value in the `aot-python` collection. A `==` whose bound computes one value **defines** the attribute, and the run writes it into every value without a derivation of its own, empty cells included. A collection lists the allowed values. Whether a declaration's trailing comparison is a bound at all is still read from the text alone: it must read as a Python expression, so `speed > none noted` stays a name.
  - **Nothing runs on a keystroke.** `Ctrl+Enter` runs a derivation with its stale upstream and everything downstream, in place, then checks the constraints. `F9` runs everything stale. The park key runs every derivation fresh before parking, and the store records what computed them. Tab, Format Document, a save and a CSV arriving compute nothing, and a copied derivation (`Ctrl+'`, a fill, the copy-down commands) arrives without a value until the next run. The end of each line says how it last ran and **when** (`✓ 3 rows · 12 ms · 16:04`), kept across restarts.
  - **How it runs.** One persistent Python process per document speaks JSON lines over stdio. pandas, numpy, matplotlib and the rest are imported only when used, and a missing one names its install command.
  - **Trust.** Python is **off by default** (`aot.python.enabled`) and never runs in an untrusted workspace. Each Python file is asked about by its path the first time a run reaches it, and again only when it changes outside the editor; a change saved in the editor is the writer's own.
  - **What the linter judges.** `verify.js` never runs Python, so it no longer audits derivations or constraints at all, parked ones included. No Python finding counts in `V`, and the linter's rule 12 now only says where a derivation may stand.
  - **Leaving the formula language.** A formula left in a file stays as text and is reported when it runs. AutoSum (`Alt+=`) went with the language.
  - See [Python](README.md#python) and [`examples/python edge cases.aot`](examples/python%20edge%20cases.aot).
- **The function a derivation calls is a link to its file.** Where a Python file of the repository defines it — the sidecar, a module (`finance.revenue`, `tools.finance.revenue`), a file named by `aot.use`, or a module the sidecar imports it from (`from helpers import load`) — the callee is underlined, and Ctrl+click opens that file at its `def`. Nothing is run to find out: the files are read, not imported. A function of the standard library or an installed package has no file here, and is not underlined.
- **Every computed number is written with thousands separators** — `1,215.6`, `184,540` — where a computed value used to copy the separators of the value it replaced. A value you typed is never reformatted. A computed year now reads `2,026`; compute text or a date when you mean a year.
- **A value that carries a derivation links to its file.** `chart: aot.files/chart.png =plot(@Sales)` is Ctrl+clickable, and hover shows the picture: the derivation after a value is no longer read as part of its path.
- **An `UNEXPECTED` line in `out/test-extension.js` now fails `npm test`.** It used to print and scroll past with the run still passing.
- **The table keys work in free text** ([`src/lineform.js`](src/lineform.js)). A Concept written as `- Example` lines is a grid too — each Example a row, each attribute a column, an Example's `attribute: value` line a cell — so every table key but `Enter` now works there: `Tab` walks the Examples' names and values, `Alt+↑`/`↓` moves a whole Example with its sub-Examples, `Ctrl+Alt+`arrows copy an Example or an attribute, `Alt+Shift+`arrows insert and delete them, the copy-cell keys carry a value to the next Example or attribute, and Ctrl+arrows, `Ctrl+D`/`Ctrl+R`, `Ctrl+'` and the rest do what they do in a grid. Every operation edits only the lines it is about, in place — nothing is reordered, declared or re-spelled, as a flip to a table and back would. On a bare attribute line `Tab` still indents, and wherever the parse finds no grid after all, a key does what VS Code does with it. A new `aot.inGrid` context gates the keys; `Enter` stays a table key alone.
- **The spreadsheet's keys, inside a table.** `Ctrl+`arrow jumps to the edge of the data exactly as Excel's does — from a filled cell to the last filled cell before a gap, from an empty one to the next filled cell, with nothing that way to the table's edge — and `Ctrl+Shift+`arrow selects as it goes; `Ctrl+Home` / `Ctrl+End` reach the table's corners (a second press, the file's); `Ctrl+A` selects the table, then the file. `Ctrl+D` **fills down** and `Ctrl+R` **fills right** — the neighbouring cell into the cursor's, or across a whole selection — `Ctrl+'` / `Ctrl+Shift+'` copy the derivation or the value from the cell above. Anywhere in a `.aot`, `Ctrl+;` / `Ctrl+Shift+;` write today's date (`YYYY-MM-DD`) and the time, and `F9` runs the stale Python and checks the constraints. The movement keys move the cursor and edit nothing; the fills never take the header or the name column as their source. See [the table editor](README.md#the-table-editor).
- **A pipe in a value is part of the value.** One pipe was all it took to make a row, so `rule: a | b` turned into a broken table and the linter asked for a broken bar instead. A name never holds a colon, so a line whose first pipe comes after a colon is now a `name: value` line, in the linter, the table editor and the highlighting alike; a row's own colons stand in its cells, after the first divider, and read as they always did.
- **An Example's name is part of what it is.** Two Examples carrying identical attributes and values were a content clash (rule 20) whatever they were called — so two payments of 100 to one shop, `P1` and `P2`, were "one idea written twice", and so was every ledger, log and bank statement. Now only Examples that share their **name** as well as their content clash; two Concepts of one content still clash whatever they are called, since a kind *is* its definition. Every clash this removes from the examples was between differently named Examples.
- **Constraints park with the derivations, and still hold.** `Ctrl+Shift+`` now takes the constraints off attribute declarations too — `age >=18`, `status ==("draft", "sent")`, `vat ==@price*0.2` — so a header reads as its column's bare name. Unlike a derivation, a bound computes nothing that could stand in its place, so a parked constraint is **still checked**: the editor reads it back out of `aot.files/<file>.formulas` and every run holds every value to it, and the attribute's name is tinted with a hover saying what binds it. A store written before this still comes home.
- **`Ctrl+K T` flips a Concept between a table and free text**, beside `Ctrl+Alt+T` — which Linux, some laptop utilities and AltGr keyboard layouts take for themselves. The flip is on the lightbulb and the right-click menu too. The README explains why the **right** `Alt` fails on AltGr layouts (it is AltGr, not `Alt`) and how to fix it in Windows.

- **`Tab` inside a table travels the cells, and only that.** It briefly also re-indented: at the head of a row's name it nested that row under the row above, and in a table's own leading indent it moved the whole table a level. Both put an *edit* on the one key a table is driven with — you pressed `Tab` for the next cell and an Example changed its place in the tree instead — and where the move was impossible, a first row having no sibling to nest under, the key did nothing at all, a dead `Tab` in the middle of a table. Now it means the next field wherever in a row it is pressed, the leading spaces included. **Indenting is what a selection of lines does**, exactly as everywhere else in the editor, and since a row's depth *is* its leading spaces that is also how a row is nested and how a whole table is re-filed under another parent; **Nest Row Under the Row Above** and **Lift Row Out of Its Parent Row** stay in the Command Palette, sub-Examples travelling with the row. An `.aot` file now also opens with four-space, spaces-only indentation (`editor.tabSize`, `editor.insertSpaces`, `editor.detectIndentation`), which is what the language requires of every line and what that `Tab` therefore inserts.

- **The column width cookie is gone, and wrapped cells with it.** A header cell could end in `<24>` to cap its column at 24 characters, and a longer value wrapped at word boundaries onto **continuation rows** — data rows with an empty name cell, each carrying the next fragment, read back joined by single spaces. Both are out: **one row of a table is one line of the file**, a column is as wide as its widest cell, and `<24>` is now nothing but part of a column's name. The cookie bought a narrow table at the price of the plainest rule the language has, and everything downstream had to know it — the linter joined fragments back into one value, the renderer split them out again, every table command travelled *logical* rows over the physical ones, and an empty name cell meant a continuation in a capped table and an error in every other. A table with one long column is now simply a wide table, and every value reads where it stands. **A file written with cookies still parses**: `<24>` reads as part of the column's name, each fragment stays the row it looks like, and the empty name cell that used to open a continuation row is reported as the error it is in every other table.

- **A table can hold an Example hierarchy.** A row indented one level deeper than the row before it is that row's **sub-Example** — what `- Child` under `- Parent` says in free text — so the grid holds a tree and not only a list, and the claim the language rests on holds in both directions: a table parses to exactly the tree its lines would. Until now every row was filed under the Concept the header names, so a hierarchy was the one thing free text could say and a grid could not, and [`Ctrl+Alt+T`](README.md#flipping-between-a-table-and-free-text) refused to convert an Example that had children. The depth is the line's own indent, four spaces to the level, exactly as the rest of the language writes depth — no new column, no adjacency list repeating each parent's name on every child, and the shape readable at a glance. A child's cells are its own: an empty cell asserts nothing, here as everywhere, and a row inherits nothing from the row it sits under. The header is the one row that cannot nest, since it names the Concept the whole table describes, so the first data row is always top-level and a row can no more skip a level than a line can; anything under one level is gutter, so a pasted `Otter | size` still reads as one flat row. **Every key that moves a row now moves the branch under it** — `Alt+↑`/`Alt+↓` hop the whole next branch rather than the next line, `Alt+Shift+↑` deletes a row with its sub-Examples, and *Sort Rows* orders each generation against its own siblings with every branch travelling whole — and a row is **nested** by indenting its line, four spaces in front of the name, the same edit that nests anything else in the language — with *Nest Row Under the Row Above* and *Lift Row Out of Its Parent Row* in the Command Palette to do it to the cursor's row, sub-Examples travelling along. The [CSV mirror](README.md#the-csv-mirror) carries the shape as a **`parent` column** rather than as indentation, because every reader of a CSV trims its cells and the indent would not survive Excel: a nesting scope gains one column naming the row each row sits under, folding back re-reads it as depth, and a flat scope gains nothing, so its CSV is byte for byte the file it always was. That also closes a quiet loss — before this, a nested Example mirrored flat and a round trip through the CSV dropped the tree. A flat table renders, sorts, parses and mirrors exactly as it did.

- **No rule, and no alignment with it.** A table's header used to be declared by the `---+---` rule under it. The rule said nothing the *order* did not — the header is the row that stands first — while costing a line of every table, a key (`Alt+-`), and a shape every reader had to skip. It is gone: a table is a header row and the rows under it, and that is the whole grammar. A rule left in an older file is **skipped without ending the table and drawn away on the next re-draw**, so Format Document is the upgrade here too. Column alignment goes with it, since the colons were written *in* the rule (`:---`, `---:`, `:--:`): every column is padded on its right to its column's width, the four **Align Column** commands are gone, and nothing written down is lost — alignment was presentation, and no crosslink, formula, CSV row or Gödel number ever saw it. A table being typed is never wrong-shaped now: one row is a header whose rows are still to come, so the fresh-table skeleton is two lines rather than three.

- **The pipe divides; it no longer borders.** A [table](README.md#tables) row used to open and close with a `|`, so every row paid two characters for a frame that said nothing — and the first column, alone in the language, started one character in from where every other line starts. The border is gone: **one divider between each pair of cells, and none at either end**. `Order|country` heads what `Acme|France` fills in, and a table is now exactly as wide as the content it holds. Everything that follows from it follows from the one rule that a **row is a line carrying a pipe** — including the one place the pipe is not a divider at all. A Concept with **no attributes** has one column of names and no pair of cells to divide, and a divider between nothing and nothing is no character at all, so such a table would come back as plain outline lines and stop being a table between one draw and the next. There the pipe **closes** the row instead — `Org Structure|` over `Department A |` — which is the same pipe doing the only job it has left. It is written wherever such a grid is drawn (a one-column CSV folded back, free text flipped over, typed by hand) and it is *read* as the empty last cell it looks like, exactly as any other trailing pipe is, so drawing it again changes nothing. The lone-cell pipe Example (`|Socrates|`, the `- ` form written with pipes) goes with the borders: it was already sayable, and better said, as a Concept with `- ` Examples. A literal pipe inside a value is written `¦`, the broken bar the [CSV mirror](README.md#the-csv-mirror) already bends one to, and a value whose stray `|` turned it into a row is told so where it stands. The rule row loses its borders with everything else (`---+---`), and a lone `-` is left to mean what it has always meant — an Example whose name is still being typed — so a rule now needs two characters to be one. A row's **depth** is no longer hidden behind the border either: it is the line's own indent, four spaces to the level, exactly as the rest of the language writes depth, and so a row written deeper than its header nests inside the table rather than ending it. Only a blank line, a line carrying no pipe, or a line shallower than the header ends a table now. The formatter draws to the same rule: a row ends at its last written cell, since padding past it is only trailing whitespace, while a row that stops short keeps the dividers of the columns it stops before, and a row whose **name cell is empty** — one still being filled — opens with that cell's own spaces so the columns below stay square. Typing `|` on an empty line still grows a skeleton, now with an empty column beside the Concept, because a table without a pipe is not a table. **A file written in the old form is migrated by Format Document**: a block whose every row still carries both borders is read without them and drawn again in the new form, which is the whole of the upgrade — the linter meanwhile reads those borders as the empty cells they now are and reports them, so nothing changes meaning silently.

- **A parked value says so.** [Parking](README.md#parking-the-derivations) leaves a file of plain values, which is what lets it stand on its own — and is also the one trap it sets: `20` in a cell looks exactly like a `20` somebody typed, so it invites being typed over, and that edit stands only until the derivations come home and recompute it. Every value whose derivation is in the `.formulas` store is now **tinted where it stands**, in the editor's inlay-hint colours, because that is what it is: a number the editor is showing you rather than one you wrote. **Hover** names the formula (`=@price*0.2`), the address it is filed under (`@Invoice@vat@INV-1`) and the store it is in, and offers **put the formulas back** as a one-click command — the place to change what a value computes. The mark is a background and **never added text**, so a marked cell keeps the width its column aligned it to and a grid stays square; the two underline styles are left to mean what they already mean (a crosslink to a Concept, a crosslink to an Example). It is drawn from the **store**, not the data, so it appears the moment the store lands and goes the moment it is deleted — by the key, by hand, or by a pull — and it resolves each address exactly as unparking would, so what is tinted is exactly what putting the formulas back would rewrite, and an address that no longer names anything is silently unmarked rather than guessed at. Off with `aot.parkedValueMarks`. New `park.parkedSpans` ([`src/park.js`](src/park.js)) does the resolution, pure as the rest of that module.
- **`Ctrl+Alt+T` flips the Concept at the cursor between a table and free text.** A table is [pure shorthand](README.md#tables-are-pure-shorthand) for the `- Example` lines it parses to, so a Concept has two spellings of one idea — and which one reads better is a question about the data, not about the model. A wide grid of short values wants to be a table; a handful of long prose values wants to be lines. The key writes the Concept out in the other one, and pressing it again writes it back. The cursor may stand **anywhere inside the Concept** — its own line, a header cell, a row, an attribute, a value — and it lands on the Concept's first line in its new form. No Example and no value is ever lost, and a derivation moves exactly as typed (`20 =@price*@tax rate` travels whole); each attribute's `(alias)` and its constraints ride on the header cell going out and on the declaration line coming back — never onto a value line, since a bound governs the attribute rather than each value of it. One reading does move, because a grid cannot hold it: an attribute a single Example only *declares* (a bare `nickname` under `- Socrates`, no value) becomes a column of the Concept with that Example's cell left empty, since a header is a table's only place for an attribute name. What a grid holds that a line cannot — a column's width, its alignment colons — is presentation of a table and comes off with it. The flip **computes nothing**: every value stays as it was written, and each derivation travels whole beside it. Nothing the flip cannot convert is restructured: a Concept's own defaults, its `...` Maps, its sub-Concepts and any Example carrying children of its own keep their lines and the grid is filed beneath them — the **merge form** the language already has. A Concept whose subtree is nothing but attributes and flat Examples flips to a **standalone** table naming itself in its first header cell, exactly where its line stood. Coming back, a header cell is a declaration, so it returns as the attribute line that declares the same column.
- **A comparison operator inside a bound's brackets or strings no longer splits it.** A declaration's bounds chain on space-preceded operators (`age >=18 <=65`), and a segment used to be believed wherever a reference vouched for it, so a bound holding `<=` inside a string was cut in two and the whole declaration fell back to being read as prose. A segment now has to close its brackets and strings before a new bound can start: `status ==("a <= b", "sent")` is one bound. A reference's name may hold spaces but never a word of Python's own, so `@price if … else …` reads as the reference and then the `if`.
- **An Example belongs to a Concept, and only a Concept's Examples are linkable.** `default-is-a-Example` and `example-is-a-Example` now resolve one way: the attribute (or its alias) must name a Concept, and the value must name an Example **of that Concept**. The old second route — an Example filed anywhere beneath an attribute of the same name — is gone, because those Examples are the vocabulary of *that* attribute in *that* frame, not a Concept's extension. One frame's `allow special value override: Ellipsis` no longer reaches another frame's `- Ellipsis`, and an attribute that names no Concept states no vocabulary, so none of its values link. A Concept's Examples still nest: `- Crimson` under `- Red` under `Hue` is a Hue, and a narrower Concept's Examples are the wider one's too — only an attribute on the way up stops the walk.

- **One `aot.files` folder per repository.** The folder is now found by walking up from the `.aot` to the nearest `.git`, rather than by asking the editor which folder happens to be open — so a repository opened by one of its subfolders, a repository opened as several workspace folders, and a `.aot` opened on its own with no folder at all all write to the **one** place, where each used to grow an `aot.files` of its own. A repository nested inside another keeps its own, since that is a different repository; a file in no repository at all still falls back to the workspace root. Everything the folder holds follows it: the [CSV mirror](README.md#the-csv-mirror), the [`.formulas` stores](README.md#parking-the-derivations), the files a value cites by path, and the tidy-up, which reads the whole repository before calling a CSV unclaimed. A folder an earlier release left elsewhere **folds into the repository's own on the next save** — the store and the copied-in evidence along with the CSVs, because leaving those behind would break the very links that name them — and a name already taken at the destination is never overwritten: that file stays where it is, and its folder with it, so the fold can lose nothing. Where the root sits above the folder the editor has open, the CSV and store watchers are extended to reach it, so a CSV edited there still folds back.
- **A CSV edited while the editor was closed now folds in, and Excel's spellings are read as what they mean.** The [CSV mirror](README.md#the-csv-mirror) is the one half of a model another program owns as much as this one does, and it had two ways of quietly losing an edit. The fold-back watcher only hears a file changed while VS Code is running — so a CSV edited in Excel with the window shut was overwritten, unread, by the next save of its `.aot`. On activation the folder is now **caught up**: every CSV saying something its `.aot` does not folds in before anything can overwrite it, one at a time, and a folder already in step does no work at all, so an ordinary launch is a no-op. **AOT: Import Edited CSVs into their .aot Files** runs the same sweep by hand. Where a CSV and its `.aot` both moved while the editor was shut the CSV is the later word, with the rails that always held: a blank cell says nothing rather than erasing, a value carrying a formula is left to its formula, and an archived `_` file is skipped exactly as the watcher skips it. The second loss was the file itself. Excel's *CSV UTF-8* writes a **byte-order mark**, which used to ride into the header's first cell — the very cell that names the Concept — and Excel writes **semicolons** wherever the comma is the decimal mark; both are now read as what they mean, while the mirror goes on writing plain commas and LF. Excel also holds a **lock** on the workbook it has open, so a save that cannot write the CSV now says which file is open elsewhere instead of throwing out of the save handler, and because Excel saves by renaming a temp file over the target, a fold-back that catches the file mid-swap retries rather than dropping the edit. One save from Excel arrives as several filesystem events, so the burst settles into a single fold rather than several racing over the same lines. Internally the whole-folder sweep builds the Concept-to-file index **once** (`ownerIndex`) where the per-CSV lookup used to re-scan and re-lint every `.aot` in the repository for each file it considered.

## [1.11.0] - 2026-07-30

**The formulas move out of the data, the editor asks about the names it cannot check, and you stop losing your place in a table.** Univocity is Alpha's first rule, and the linter has only ever proved the half that can be proved — the *same* name written twice must mean the same thing. The other half is not provable at all: two *different* names may still be one idea, and nothing in the tree records that `Client` and `Customer` are the same word in two dialects. So the editor now **asks**, dismissibly. Alongside it, three ergonomics: a table's header pins itself while you scroll, copying and cutting have keys of their own, and a possessive stops being read as a plural.

- **`Ctrl+Shift+`` parks the derivations out of the data** ([`src/park.js`](src/park.js)), and the same key puts them back. The order is the whole design: the **recompute runs first**, so every derived value is materialised where it stood, and only then do the formulas leave for `aot.files/<file>.formulas`; the tables then re-align and the columns narrow to their data. **The parked file still stands on its own** — every value is present, it reaches the same `V`, and `node verify.js` judges what is in front of it and never reads the store. A parked file is not a file with holes in it; it is a file whose arithmetic has already been done, and nothing in the linter, the CSV mirror or the cross-file reconcile knows the store exists. Each derivation is addressed with the **`@` path the language already uses** — `@Invoice@vat@INV-1` — and because a table and a `- ` list are one idea in two spellings, that one address finds the Example whichever way it is written. Bounds never park (`age >=18` is a rule about values, not a recipe for one) and neither does a `==` definition (already written once, where the attribute is declared). A cell holding **only** a formula parks too, leaving the value the recompute wrote. Nothing is ever invented back: an address whose row was renamed while it was parked is reported and **kept** in the store rather than guessed at. The store's existence is the state — commit it beside the `.aot`, since it is the only copy of the derivations while they are out.
- **Two names for one idea** (new warning rule 14, [`src/synonyms.js`](src/synonyms.js)). Two Concepts whose names match word for word once each word is mapped to its synonym group (`Sales Client` / `Sales Customer`, `Fix Defect` / `Repair Bug`), or once each is cut to a shared prefix of six characters (`Governance` / `Government`). **Repo-wide** — `Client` here and `Customer` in the file next door is the pair worth catching — and reported on **both** sides, each carrying a Ctrl+clickable link to the other. Three things end the question: the lightbulb's preferred **Rename '`X`' to '`Y`'** (through the rename engine, so every reference follows as `F2` would move it), writing the **alias** `Human (Natural Person)` — a declared second name is never raised — or the second lightbulb, which records the pair in `aot.distinctConcepts` and never asks again, in either order and in any file. Advisory, never counted in `V`; off with `aot.synonymWarnings`. The vocabulary is deliberately small and domain-shaped rather than a thesaurus, since a thesaurus makes near-synonyms of words a model must keep apart (`cost` / `price`). Names differing only in **number** are left to the singular-Concept warning, only in **case** to univocity.
- **A table's header pins itself as you scroll it.** The extension now publishes the parsed tree as **document symbols**, which makes a grid's header line the *parent* of its rows — so VS Code's own **sticky scroll** holds it at the top of the viewport, exactly as it holds an enclosing Concept. A grid written in the merge form (the Concept on its own line above) gets the same nesting, so the header pins either way. The freeze is the editor's, not a fake, and it costs nothing: the tree was already parsed. The same symbols fill the **Outline** view and the **breadcrumbs**. Across the table, where nothing can pin the name column, the **status bar** names the cell instead — `Person ▸ Socrates ▸ occupation`, the Concept, the row's Example and the column's attribute — which reads the same however far right you have scrolled, and names the *column* too.
- **Copy, cut and move are three different keys.** `Alt+`arrow still **moves** a row or column; `Ctrl+Alt+`arrow now **copies** it (header and every value); `Ctrl+Alt+Shift+`arrow copies the **cell** into its neighbour and follows it there, so holding the key fills a run. Unlike the formula copies, these carry the text exactly as written, formula and all — copying a row is how the next Example is usually made. Cutting a cell into its neighbour is four more palette entries (**AOT Table: Cut Cell Up / Down / Left / Right**), unbound by default. A vertical copy skips the separator as `Tab` does, and copying down past the last row appends one; sideways never grows the table, because a new column needs an attribute name of its own.
- **An Example under an attribute no longer becomes a row of the Concept's CSV.** `- draft` and `- sent` under `status` are the values the attribute is allowed to take, not more invoices — the mirror was filing them beside `INV-1`. The scope walk now stops at an attribute rather than descending through it, which also drops the refinements nested under those.
- **A possessive is not a plural.** `Aristotle's` is a fine Concept name; the `'s` says whose the idea is, not how many there are. It comes off before `pluralize` judges the word — which also catches the plural possessive `Farmers'` that `pluralize` did not recognise as a word at all. An apostrophe is a letter of a name everywhere else too: the grammar no longer ends a Concept's colouring at one, and typing `'` no longer conjures a closing partner (the language's verbatim marker is the backtick).
- **README:** two new sections. **[Incompleteness is a feature](README.md#incompleteness-is-a-feature)** — `V = 0` claims that nothing written down contradicts anything else, never that everything is written down; Gödel's exponent 0 says silence is representable, and the four places the language makes that concrete. **[The model is unbalanced until all four are used](README.md#the-model-is-unbalanced-until-all-four-are-used)** — drop one of the four causes and the explanation is not shorter but lopsided, with a table of how each absence shows.
- **Tests:** new `out/test-synonyms.js` (19 checks) and `out/test-park.js` (17 checks) join `npm test`; the table operations and the outline/status bar are covered in `out/test-table.js` and `out/test-extension.js`. Seven stale expectations in `out/test-extension.js` — the CSV mirror's pre-1.9 `name` header, the pre-1.9 table skeleton, and the cross-file duplicate warning 1.10 removed — were corrected to what the code has done since those releases.

## [1.10.0] - 2026-07-25

**A Concept written in two files is one idea, and the editor keeps it that way.** Alpha used to have a single answer for a name appearing twice — "duplicate, pick one" — and a Reconcile fix that merged what it could by name and then **deleted the other file's whole block**, taking with it every Example the two happened to share, every value they set differently, and every column the kept table had no header for. It is gone. In its place the language draws the distinction logic already gives a Concept: its **intension** (attributes, values, the kind it is filed under) is univocal and reconciled for you on save; its **extension** (the Examples it lists) is a partial sample per file, unioned across the repo and never merged away. Full write-up: [docs/features-1.10.md](docs/features-1.10.md).

- **Every occurrence is a peer.** No file owns a Concept. Two files each listing the motivations their own subject needs — `Jakus` with one in `monthly close.aot` and four in `bank recon.aot` — are not in conflict and no longer report as anything. See the new [Concepts across files](README.md#concepts-across-files).
- **Saving a file makes it agree with the repo.** An attribute or value a peer declares and this file does not have in force is **written in**, including onto a same-named Example (an Example has an intension too) and as a new column on a table. Additive only: nothing you wrote is ever deleted, and no other file is touched — saving `monthly close.aot` writes to `monthly close.aot` alone, so peers converge as you save each. One side saying less is never disagreement; an attribute a peer merely *inherits* is already in force here and is not copied in. Off with `aot.autoReconcile`.
- **One `...` line says where the rest of the Examples are.** `... 4 more in bank recon.aot:2` — the total first, then `file:line` locations that **Ctrl+click** straight to that Concept, truncating at three peers with `, …`. Hover it for the whole extension, every Example a link to where it is written. A `...` **you** wrote is never touched: only the maintained shape is rewritten, so `... still to do` sits beside it untouched. A Concept written as a **table** carries the line one level under its grid: a table names its Concept in its first header cell, so one level under the grid is one level under the Concept, and a `...` written there now belongs to **the table** rather than to the row it follows — which is what lets the next pass find it and keep it true instead of writing a second one under the last row, once per save. Any stray an older save left there is cleared at the same time. (A row that needs a `...` of its own is written in line form, where it has a line to hang one under.)
- **The two decisions a tool may not take are errors, counted in `V`** (new rules 22–23): one attribute carrying **two values**, and one Concept filed under **two kinds**. Both report on *every* side at once, at the lines that disagree, each pointing at the others. The lightbulb on a value clash offers **Set '`attr`' to '`value`' everywhere**, which rewrites every file in one go. `V` is now "the file's violations given the repo it sits in" — a file linted on its own, or `lint(text, rootName)` with no repo argument, is judged entirely on its own terms as before.
- **The command line follows.** `node verify.js --workspace [dir]` lists every shared Concept and reports both sides of every contradiction, **exiting `1`** so CI can gate on it; `--reconcile` writes the agreement in first. Both are idempotent — a second run over a repo already in step changes nothing.
- **`AOT: Reconcile Concepts Across Files`** sweeps files that were never open when a peer changed. The `aot.reconcileConcept` command and its lossy merge are removed, along with `derive.diffConcepts`, `conceptDiffClause` and `mergeConceptOps`.
- **New:** [`src/repo.js`](src/repo.js), `out/test-repo.js` (40 checks), and the clean repo pair [`examples/monthly close.aot`](examples/monthly%20close.aot) / [`examples/bank recon.aot`](examples/bank%20recon.aot), both verifying at `V = 0` and unchanged by a second `--reconcile`. The README's six references to a long-missing `examples/example.aot` now point at [`examples/thought.aot`](examples/thought.aot).

## [1.9.0] - 2026-07-24

**The Concept moves into the table, and `==` says what a value is.** A table no longer sits indented under a separate `Concept` line with a `name` label in its first column — the **first header cell now names the Concept the table describes**, and the grid stands exactly where that Concept's line would, one level shallower. `|Person|residence city|occupation|` *is* the Concept `Person` and its attributes; the rows beneath are its Examples. Alongside it, a determinate `==` on an attribute stops being a bound to check and becomes the **definition** of every value it governs, so a derived column is written once in its header instead of once per cell.

- **The first header cell is the Concept** (breaking). It is capitalised like any Concept and declares the attributes after it; a **lowercase or empty first cell is an error** with a migration hint (the old `name` label is gone). Every data row is an Example filed under that Concept, exactly as before — only the heading changed. A capitalised *column* after the first is still an error, and the header's first cell may carry a `(alias)` naming the Concept, just as an attribute cell can.
- **A Concept keeps its line-form facts beside the grid (merge form).** Give the Concept its own line and repeat its name in the first header cell: the table *fills that Concept in* rather than declaring a twin, so its `tax rate: 0.2` defaults, its `- ` Examples, and the grid's rows all belong to the one Concept — and cell formulas still read the line-form defaults by name (`=@price*@tax rate`). A table filed under an `- Example` merges into it the same way.
- **References, crosslinks, the CSV mirror, and F2 all follow.** `@Person@occupation@Socrates` resolves a table by the Concept its own header names; the first header cell underlines and Ctrl+clicks as a Concept, and renaming it (F2) rewrites the header cell and every reference to it. The union CSV's first column is now headed by the **Concept name** (`Integer,is prime`) rather than `name`, mirroring the grid. `@Person` inside Person's own grid is *not* a reference to its name column — the Concept names the table, not a column.
- **Creating a table** still takes one `|`. Typed under a Concept the skeleton arrives with that Concept's name already in the first cell and the cursor in the data row; typed at the top level the first cell is left empty and the cursor waits there to name the Concept. **Create Table from Selected Lines** keeps the first cell as written (the Concept) and lowercases the rest into attribute columns. Two standalone tables in a row need a blank line between them, or the second's header reads as the first's data.
- **`==` defines rather than bounds.** A determinate `==` on an attribute declaration — `vat ==@price*@tax rate`, on a header cell or a bare line — says what the value **is**, so it is the derivation for every value of that attribute and no cell repeats the formula. Defined cells fill themselves (an **empty** one included), correct themselves on the next recompute, and carry the **value alone** — the formula lives once, where the attribute is declared. A value's own `=` formula still wins (the nearer word), and a `==` that cannot compute leaves its values untouched, erroring once against the declaration. A value that differs from its definition now reports as **stale** ("it recomputes…") rather than as a breached constraint.
- **`==or(…)` is still a bound**, not a definition: alternatives held together name no single value to derive, so listing allowed values (`status ==or(\`draft\`,\`sent\`)`) keeps checking membership exactly as before. The two readings come off the same rule — whether the bound computes to a `Choice`.
- **A line-form formula can name the Concept's own defaults.** `=@price*@tax rate` on a value under an `- Example` now resolves `tax rate: 0.2` stated on the enclosing Concept, and a silent Example inherits it — the reading a grid cell already had through its enclosing scope, which the line form was missing. This also makes the audit agree with the recompute, so a legitimate `==@price*@tax rate` column no longer reports a false "does not compute".
- **Old tables still parse for the mirror.** `tablesOf` (used by the CSV mirror, even on an unparseable file) falls back to the nearest shallower line when a table's first cell names no Concept, so a pre-1.9 `|name|…|` grid is still found and named — it just squiggles in the editor until its first cell is updated. The reference model (`examples/spreadsheet.aot`, `examples/features.aot`) is rewritten to the new form and verifies at `V = 0`.

## [1.8.0] - 2026-07-23

**The editor keeps the model whole** — a duplicate shows both halves and offers to merge them, numbering maintains itself without breaking a reference, a wrapped table stays one table. Full write-up with runnable edge cases and the tests behind each: [docs/features-1.8.md](docs/features-1.8.md).

- **Every duplicate reports at both of its places.** Same-file duplicate Concepts, identical siblings, shared aliases, differentia twins, case-twin Examples, Gödel clashes, and the cross-file duplicate all squiggle at **every** occurrence, each diagnostic carrying its partners as clickable related locations. Deleting one definition clears the other file's warning **live** — every open `.aot` re-analyses when the workspace index changes.
- **A cross-file duplicate says how the two differ and reconciles on a click.** The warning ends with the computed difference (is-a home, attributes/Examples/values only one side carries, or `identical content`), and its lightbulb offers **Reconcile: keep this definition** — the other file's missing facts merge in (rows onto a table, `- ` lines otherwise), its block is deleted, both files save. A definition holding sub-Concepts refuses the automatic merge.
- **Case never makes a second name.** Univocity, identical siblings, the file-name repeat, and the differentia signatures now compare case-insensitively, as references always resolved — `Foo`/`FOO` is one name to the checks too.
- **Numbering** ([README](README.md#numbering)). `- 1. Mix` opts an Example list in: on save/format all siblings number sequentially and every same-file reference follows through the rename engine. `1. ` on a Concept numbers its whole scope — `1. `, `2. ` at the top, `1.1` / `1.1.1` down the is-a chain; a Concept under an Example/attribute numbers only that parent's Concepts. Deleting any one number strips the scope, parents included. Prefixes are **presentation, never identity**: resolution strips them, so `trip` still types by `1. Trip`, `@Trip@…` still resolves, and no reference is rewritten by numbering or un-numbering.
- **A column can declare its width, and long cells wrap.** `|description <24>|` caps the column with an org-style cookie; longer plain cells wrap at word boundaries onto continuation rows (empty first cell), the value reading back joined — crosslinks, formulas, the CSV mirror, and rename all see the whole value. Name, header, and formula cells never wrap. Cookie-less tables are untouched, byte for byte.
- **The Example dropdown works inside table cells.** A cell in a Concept-typed column offers that Concept's Examples (archived CSV values after), exactly as the line form does; `|` triggers it on entering a fresh cell.
- **A spelling suggestion applies in one stroke.** Each suggestion is a **Replace with 'X'** Quick Fix, preferred when it stands alone — `Ctrl+.` `Enter` fixes it.
- **Dependency arrows ride only on attributes.** The inlay chain (`→Person→Address`) appears only on attribute-is-a-Concept lines; a Concept containing or aliased to another names a kind, not a dependency, and carries no arrow.
- **`...` quiets drift on either side.** No drift toward a Concept carrying `...` and none away from a home carrying it — Map child or `- ...` Example alike; what is missing is declared, not forgotten.

## [1.7.0] - 2026-07-19

**Armstrong's axioms police the dependency graph.** The declared Concept-dependency graph — the one behind `--depends`, the hover and the inlay chains — is now held to the axioms it is named after, in the lint pass itself. Each of the six axioms is accounted for: Reflexivity and Transitivity as the rules below, Augmentation / Union / Decomposition / Pseudotransitivity documented as inexpressible over single-attribute edges (README, [Armstrong's axioms](README.md#armstrongs-axioms-dependency-inference)).

- **A dependency cycle is an error, counted in `V`** (error rule 21). A Concept resting on itself through other Concepts — `Shares Outstanding ─tensor→ Tensor ─shares outstanding→ Shares Outstanding` — derives only `X → X` (Reflexivity, trivially true), so the loop asserts nothing while leaving every member defined through the others. One error per attribute carrying an edge of the loop, pinned to its declaring line — removing any one breaks it. Structural like the subsumption pass: no Examples needed, not gated behind rules 1–16, current file only.
- **A redundant direct dependency is a warning** (warning rule 11, always on, never in `V`). A direct edge that a chain through another Concept already implies — `share` on `Shares Outstanding` when `─tensor→ Tensor ─share→ Share` already reaches it — adds nothing by Transitivity. Two attributes of the same type (`from node` / `to node`) never imply each other: the witnessing chain must pass through an intermediate Concept. The inferred-FD warnings renumber to rules 12–13 to make room.
- **Recursion stays legal.** An attribute of a Concept's own kind (`parent measurement` on `Measurement`) is direct self-reference — Reflexivity makes `X → X` trivially true, so it declares nothing and is never an edge, never flagged.
- **The inferred FDs report a minimal cover.** An `X → Z` that `X → Y` and `Y → Z` already give follows by Transitivity: it is held off the squiggle channel, and `--fd` prints it tagged `[implied by 'x' → 'y' → 'z']`. A member of an equivalence is never pruned, so no consequence is lost to the pruning order.
- `examples/spreadsheet.aot` currently demonstrates both findings (the `Shares Outstanding ↔ Tensor` loop, and the direct `share` edges the chains imply) — it stops verifying until the loop is broken. The reference model still verifies at `V = 0`, with one new redundancy warning (`said of` on `Measurement`, implied via `Time`).
- **The CSV mirror no longer waits for an opt-in.** A line-form Concept mirrors out to `aot.files` on its first save exactly as a table does — attribute values or bare names alike, CSV present or not. A table and a `- ` list are one idea in two spellings, so the same Examples create and keep the same CSV whichever way they are written.
- **A cited file's link prefers the repo's own copy.** Ctrl+click on a file-path value that still names a path outside `aot.files` opens `aot.files/<name>` when a file of that name is held there, and the hover names the same target — the copy is the one that travels with the repo. The value as written is untouched: the lightbulb still offers **Copy '<name>' into aot.files** to rewrite it.

## [1.6.0] - 2026-07-18

**Tables and free text are one notation** — everything works the same in both, and each can be used in conjunction with the other. One breaking change. Full write-up with runnable edge cases and the tests behind each: [docs/features-1.6.md](docs/features-1.6.md).

- **Positional `@N` references are removed** (breaking). References are name-only everywhere: write `@price`, never `@2`. A digits lead after `@` still names an **Example** (`@Integer@35@is prime` — a Concept whose Examples are numbers needs exactly that), it just never numbers a column. A formula still using `@2` errors with a migration hint.
- **One reference registry for both notations.** The grid-only table registry is gone; every Concept answers cross-references through one tree-built scope whether its Examples are `- ` lines, table rows, or both. So `@Concept@attr` now reads a **table-formed** Concept's own free-text default too, cross-references and aggregates see the merged Example set, and a table filed under an `- Example` (`@test 1@…`) keeps answering.
- **Free-text attributes and values work in conjunction with a table.** A cell formula reads the enclosing Concept's line-form attributes by name (`=@price*@tax rate` with `tax rate: 0.2` stated on the Concept), an **empty cell inherits the Concept's default** exactly as a silent `- Example` does, an in-table aggregate also ranges over the Concept's `- ` Examples, and a line-form sibling Example can be named in a cell reference. The grid always wins a shared name, so no existing formula changes meaning.
- **The CSV mirror is one union file per Concept.** Rows are every Example in the Concept's scope — table rows and `- ` Examples together, and a table under an `- Example` mirrors into the **first Concept up the tree**; columns are the union of every attribute any of them carries, blank where a row is silent (inherited defaults fill in). Editing the CSV folds back by Example name wherever each lives: a table row updates within its table's own columns (redrawn aligned), a line-form Example attribute by attribute, a fresh name lands in the Concept's own shape. A valued cell whose table lacks the column is left to the tree — columns arrive when a table is created, never from the mirror — and the fold never deletes anything.
- **Multiple constraints chain on one declaration.** `age >=18 <=65` bounds the attribute both ways — bare lines and header cells alike, any number of bounds — each checked and reported on its own span, an operator inside a bound's `or()` or backtick string never splitting it. (Previously the second bound silently became part of the first bound's formula.)
- **`^` and `ln()` in formulas.** `^` is power, binding tighter than `*` and associating right (`2^3^2` = 512); `ln(x)` is the natural log and wants a positive number.
- **A `- ` Example that is a file path links.** `- aot.files/Person.csv` Ctrl+clicks open like any value or cell link, and an Example that is an **image** shows its picture on hover — an Example may *be* a file, exactly as a table row may.
- **Drift needs both sides to assert something.** The Concept an Example is filed **under** must now own at least one explicit attribute (declared on it or beneath it — inherited never counts), matching the guards that already held the Concept drifted toward. A home that declares nothing states no differentia to hold or release an Example by, so no drift is reported from it.
- **A new table arrives with its inherited columns.** Typing `|` on an empty line still grows the skeleton in one keystroke — and attributes the enclosing line inherits from its ancestors arrive as ready-made columns. Creation-time only (a table is never re-columned later), and the parent's own attribute lines stay out: they already declare, and a same-named column would be a duplicate.
- **Type constraints are removed from the language** (landed after 1.5.0). `birth date is date`, `is number`, `is text` are no longer constraints — a phrase like `colour is red` or `birth date is date` is simply a plain attribute name again. A constraint is a **comparison bound** only: `>= > < <= ==`, with `or()` listing allowed values. Date-aware comparison stays: two ISO dates still compare chronologically.
- **A breached constraint is a warning, not an error** (landed after 1.5.0). `age: 15` under `age >=18` squiggles yellow on the value, naming the bound and its declaring line, and is **not** counted in `V` — data out of bounds is worth knowing, not a broken file. A constraint whose bound cannot compute is still an error on the declaration.

## [1.5.0] - 2026-07-17

A batch about **referring to things**, and about the values you refer to them by. Full write-up with runnable edge cases and the tests behind each: [docs/features-1.3-1.5.md](docs/features-1.3-1.5.md).

- **A Concept's own value is reachable.** `@Measurement@alias` reads the value a Concept states on its own line — the default its Examples inherit — with no Example named. A Concept holds two kinds of thing, Examples and values of its own, and only the first used to be reachable; a Concept now earns its place in the reference registry by holding either. Only a Concept offers this reading: a table is rows and nothing else, so `@Order@price` still needs its Example named, and a Concept that states no value for the attribute says so and points at its Examples.
- **A Concept written line-form is referenced exactly like a table.** `@Integer@35@is prime` now resolves: a Concept's `- Example` children are the rows and the attribute names beneath it are the columns, so the same reference works whichever shape the Concept is written in. An Example silent on an attribute answers the Concept's own default (inheritance, as ever). Line form has no columns to number, so a number there names an **Example** — which is what a Concept whose Examples are numbers (`- 1`, `- 35`) needs. A table still wins its own name: it is the sharper reading of the same rows. `verify.js` resolves them identically.
- **A local attribute no longer shadows the Concept it points at.** `alias: =@Person@alias@Socrates` used to fail with "@ pairs a column with an Example" whenever the owner had its own `person` attribute, because a leading name was read as foreign only when it matched *nothing* local. The local reading is still tried first — so no formula that resolved before changes meaning — but a foreign Concept now also gets its turn when the local reading **cannot be completed**. Aggregates read the same way (`sum(@Prices@price)` past a local `prices`).
- **Values are answerable to the Concept that types them.** `person: James`, where `Person` lists Socrates alone, is hinted: *'James' is not an Example of Concept 'Person'* — with a Quick Fix, **Add 'James' as an Example of 'Person'**, that lists it in whichever form the Concept is already written (a table row, or a `- James` line), cursor left on the new Example. Advisory only: a gap in the model, not a contradiction in it, so it hints like spelling and never counts in `V` (off with `aot.exampleHints`). Three guards keep it to values genuinely trying to name an Example — the Concept must list Examples, the value must be the same *kind* of value they are (`maximum worker pool: 1` measures the pool), and a truth value never nominates (`present in: False`).
- **F2 renames a name everywhere it is meant.** A Concept, an Example, or an attribute — line-form or a table's header or first-column cell — renames as one edit: the declaration, every crosslink that resolves to it, and every formula reference. The rename does not guess at text: it runs the evaluator itself over every formula (an instrumented walk that records the exact span each `@` resolved), so `@price`, `@total@Acme` and `@Order@price@Acme` follow their declaration exactly as they would evaluate, and an `@2` or an alias — which never carried the name — stays put. An attribute renames with its whole scope: the same-named copies its host's Examples carry, and the ancestor declaration whose constraint governs it. Renaming a Concept carries the attributes wearing its name (the crosslink), and the formulas reading those attributes follow in turn. Case follows the span, not the typist: a span that is all lowercase today — an attribute name, its alias — takes the new name lowercased, every other span takes it as typed, so renaming Concept `Integer` to `Integer Test` writes `age (integer test)` on the attribute and `@Integer Test` in the formula. Current file only: a reference from another file keeps its name and shows its own finding there. And the editor tells you when F2 is the right tool: standing in a name that is used elsewhere shows faint ghost text at the end of the line — *2 uses elsewhere — F2 renames them all* — counting exactly what F2 would edit, so a hand edit never strands references unwarned; a name nothing uses shows nothing. Standing in a **usage** — an attribute wearing a Concept's name, a value naming an Example — is genuinely ambiguous: typing is the right move when this one reference should point somewhere else. So there the ghost text presents the choice instead of pushing a key: *names 'Person' — F2 renames its 2 uses, typing changes just this one*.
- **Table formulas recompute themselves.** A stale cell — `15 =@2*2` after the referenced value changed — used to warn and wait for Tab or Format Document; now it refreshes exactly as a line-form value does: when the cursor leaves the line, and on save. Never under a cursor and never mid edit-burst, so it cannot fight your typing. The fill touches only tables whose **values** changed — a table you are still shaping stays exactly as typed, however ragged — and when a fresh value widens its column, the block redraws whole, as Tab would draw it. Tab, Format Document and *AOT: Recompute Formulas* still force the matter; the stale warning now says what actually happens.
- **Logical operators**: `and(a,b,…)`, `or(a,b,…)`, `not(a)`, `xor(a,b,…)` in any formula or constraint. A value is true when it is a non-zero number, `yes`/`true`, or any non-empty text; false when `0`, `no`/`false`, or empty.
- **A constraint can list the allowed values**: `status ==or(\`draft\`,\`sent\`,\`paid\`)`. It is the same `or()`, not a second one — `or()` answers with its alternatives held together, and that reads as a **truth** in a formula (true when any is true, exactly logical OR) and as a **set** wherever `==` compares against it. An ordering distributes the same way.
- **A value may hold a literal `=`** by escaping it: `note: a \= b` is the value `a = b`, not a derivation. The backslash belongs to the file, not the model — the value reads as `a = b` everywhere (crosslinks, Gödel numbers, formulas, CSV) while the line keeps its escape through every rewrite.
- **Text is a first-class thing**: `concat` `proper` `find` `contains` `starts` `ends` `substitute` `split` `repeat` `pad` `text` `value`, beside the existing `upper`/`lower`/`trim`/`len`/`left`/`right`/`mid`/`replace`. `find()` answers a 1-based position and `0` when absent, so it reads as a truth. See [Working with text](README.md#working-with-text).
- **The CSV mirror reaches line-form Concepts.** A CSV named after one folds its rows in **as Examples, merged by name** — not as a table: a CSV arriving is data, and data is no reason to restructure a tree you wrote deliberately. A blank cell says nothing rather than erasing, and a derived value is left to its formula. The Concept mirrors back out on save, but only where a CSV of its name is **already in the folder** — that CSV is the opt-in, or every Concept with Examples would rain a file into `aot.files`.
- **Archived CSVs feed the completions.** A `_Person.csv` is still never folded back, but the values in it were real once: they are offered where a `person:` value is typed, after the live Examples and marked `archived in _Person.csv`.
- **A file you cite can be brought in.** The lightbulb on any file-path value outside `aot.files` offers **Copy '<name>' into aot.files**: the file is copied in and the value rewritten, so a model travels with its evidence. Same bytes already there → relinked, no write; different → asks, and offers to keep both. A CSV any value points at now counts as claimed, so the tidy-up never archives the file a link names.
- **Cross-platform correctness** (Windows / Linux / macOS): the workspace index is keyed case-blind where the file system is, so the same file arriving as `C:\repo\A.aot` and `c:\repo\A.aot` is one entry and never its own duplicate Concept; `underWorkspace` compares path segments, so a sibling `/repo-two` is no longer read as inside `/repo`; and CRLF/LF is not a difference to the CSV mirror, so a file back from Excel or git is not rewritten on every save.
- **What Alpha costs an LLM, measured** rather than asserted: [`out/token-experiment.js`](out/token-experiment.js) and the README's [What it costs to think in Alpha](README.md#what-it-costs-to-think-in-alpha). The saving is mostly in the **tree** (57%, 4.3 tokens per is-a edge against 10.1), modest in the **grid** (23% at 100 Examples, growing with size), and **negative below ~5 Examples**. The real economy is that the questions never reach the model at all.

## [1.1.42] - 2026-06-20

- Gödel numbering (`src/godel.js`): a second characteristic number `G(n)` that encodes a line's **content**, complementing `chi`, which encodes only its **ancestry**.
